Interactive CSS-Based Web Navigation System

A responsive navigation bar built with HTML and CSS only — no JavaScript. Resize the window, hover the “Techniques” menu, use the Tab key, and click the links to see it work. The sections below document the design, implementation, testing and optimization.

1. Design

ObjectiveFast, accessible navigation without scripts.
DesktopHorizontal bar, dropdown on hover and keyboard focus.
Mobile (≤720px)Hamburger toggles a stacked menu.
ThemeLight/dark via prefers-color-scheme.

Structure

Semantic markup: <header> → <ul> list of links → nested <ul class="sub"> for the dropdown. Colours are CSS custom properties so the theme is defined once.

2. Implementation

Checkbox hamburger

A hidden checkbox stores the open/closed state; a <label> toggles it. The sibling selector shows the menu.

#toggle:checked ~ .menu { display:flex }

Hover / focus dropdown

:focus-within makes the same menu work for keyboard users.

.has-sub:hover > .sub,
.has-sub:focus-within > .sub { opacity:1; visibility:visible }

Active-link highlight

The :has() selector highlights the link for the section in the URL hash, with no scroll-spy script.

html:has(#design:target) .menu a[href="#design"]{ background:var(--brand) }

Other features

  • Sticky header (position:sticky)
  • Smooth scrolling + scroll-padding-top so headings are not hidden
  • Hamburger icon animates into an “X”
  • Respects prefers-reduced-motion

Browsers / devices to test

Chrome, Firefox, Safari, Edge; Android and iOS phones; Chrome DevTools device mode at 320, 375, 768 and 1280px. Use Lighthouse (Accessibility) and the axe extension for automated checks.

Note: :has() and color-mix() need recent browsers; older ones simply skip the active highlight and tinted hover while links keep working.

4. Optimization

  • Zero JavaScript — no parse/execute cost, no blocking scripts.
  • Single file, no external requests — no images or web fonts; system font stack avoids layout shift.
  • Compositor-friendly animation — only opacity and transform are animated.
  • CSS variables — one theme definition, less repeated CSS.
  • Accessibility — semantic lists, ARIA label on the toggle, 44px touch target, focus styles, reduced-motion support.
  • Next steps — minify CSS, add aria-expanded via a small JS enhancement if screen-reader announcements are required.
Conclusion: a fully responsive, keyboard-friendly navigation system can be delivered with CSS alone, keeping it light, fast and easy to maintain.
